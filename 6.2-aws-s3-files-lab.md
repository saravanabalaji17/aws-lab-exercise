# Lab Exercise – Create and Mount Amazon S3 Files on EC2

## Lab Objective

In this lab, you will:

* Create an S3 bucket
* Create an Amazon S3 Files file share
* Create an EC2 instance
* Configure the required Security Groups
* Create and attach an IAM role
* Mount Amazon S3 Files on EC2
* Create folders and files
* Delete folders and files
* Validate all operations

---

# Prerequisites

* AWS Account
* AWS CLI configured
* Existing VPC
* Internet Gateway
* Key Pair

---

# Lab 1 – Create an S3 Bucket

1. Open **AWS Console**
2. Navigate to **Amazon S3**
3. Click **Create bucket**

Configure:

| Setting             | Value                 |
| ------------------- | --------------------- |
| Bucket Name         | demo-bucket-lab-001   |
| Region              | Same region as EC2    |
| Object Ownership    | Bucket owner enforced |
| Block Public Access | Enabled               |

Click **Create bucket**.

### Validation

The bucket status should be **Available**.

---

# Lab 2 – Create an IAM Role for EC2

Go to:

**IAM → Roles → Create role**

Trusted entity:

* AWS Service
* EC2

Attach these AWS managed policies:

* `AmazonS3FilesClientFullAccess`
* `AmazonS3FilesClientReadWriteAccess`
* `AmazonS3FullAccess`

(Optional: use a custom least-privilege S3 policy instead of `AmazonS3FullAccess` for production.)

Role name:

```text
EC2-S3Files-Role
```

Create the role.

### Validation

The role is listed with all three policies attached.

---

# Lab 3 – Create a Security Group for EC2

Create a security group named:

```text
EC2-S3Files-SG
```

### Inbound Rules

| Type | Protocol | Port | Source |
| ---- | -------- | ---- | ------ |
| SSH  | TCP      | 22   | My IP  |

### Outbound Rules

| Type  | Protocol | Port | Destination                                       |
| ----- | -------- | ---- | ------------------------------------------------- |
| HTTPS | TCP      | 443  | 0.0.0.0/0                                         |
| NFS   | TCP      | 2049 | S3 Files Security Group (or VPC CIDR if required) |

Save the security group.

---

# Lab 4 – Create a Security Group for Amazon S3 Files

Create another security group:

```text
S3Files-SG
```

### Inbound Rules

| Type | Protocol | Port | Source         |
| ---- | -------- | ---- | -------------- |
| NFS  | TCP      | 2049 | EC2-S3Files-SG |

### Outbound Rules

Allow All (default).

### Validation

The security group is created successfully.

---

# Lab 5 – Launch EC2 Instance

Launch a new EC2 instance.

Configuration:

| Setting        | Value             |
| -------------- | ----------------- |
| AMI            | Amazon Linux 2023 |
| Instance Type  | t3.small          |
| Key Pair       | Existing Key Pair |
| IAM Role       | EC2-S3Files-Role  |
| Security Group | EC2-S3Files-SG    |
| Storage        | 20 GB gp3         |

Launch the instance.

### Validation

* Instance state = **Running**
* Both status checks pass.
* SSH login succeeds.

---

# Lab 6 – Create Amazon S3 Files File Share

Open:

**Amazon S3 → Files**

Click **Create file share**.

Configure:

| Setting         | Value                 |
| --------------- | --------------------- |
| File Share Name | lab-s3files           |
| S3 Bucket       | demo-bucket-lab-001   |
| Access Mode     | ReadWrite             |
| VPC             | Same VPC as EC2       |
| Subnet          | Same subnet/AZ as EC2 |
| Security Group  | S3Files-SG            |

Create the file share.

### Validation

Status:

```text
Available
```

---

# Lab 7 – Connect to EC2

```bash
ssh -i lab.pem ec2-user@<EC2-Public-IP>
```

Confirm the IAM role:

```bash
aws sts get-caller-identity
```

### Validation

The role ARN is displayed.

---

# Lab 8 – Create the Mount Point

```bash
sudo mkdir -p /mnt/s3files
```

Verify:

```bash
ls -ld /mnt/s3files
```

---

# Lab 9 – Mount Amazon S3 Files

Use the mount command provided in the AWS Console for your file share. It typically resembles:

```bash
sudo mount -t nfs4 <S3Files-Mount-Endpoint>:/ /mnt/s3files
```

### Validation

```bash
df -hT /mnt/s3files
```

Expected:

```text
Filesystem      Type
127.0.0.1:/     nfs4
```

---

# Lab 10 – Verify the Mount

```bash
mount | grep s3files
```

Expected output should include:

```text
nfs4
```


# Cleanup

Delete the following resources to avoid ongoing charges:

1. Unmount the S3 Files share.
2. Terminate the EC2 instance.
3. Delete the Amazon S3 Files file share.
4. Empty and delete the S3 bucket.
5. Delete the IAM role (if created only for this lab).
6. Delete the security groups (if no longer in use).
