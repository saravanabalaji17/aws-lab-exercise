# AWS Network Load Balancer (NLB) Lab Exercise

## Objective

In this lab, you will:

* Launch **2 EC2 instances**
* Install and configure **Apache Web Server (httpd)**
* Create a **Network Load Balancer (NLB)**
* Create a **Target Group**
* Register both EC2 instances
* Validate load balancing using a browser and `curl`
* Stop the web server on one instance and verify the NLB health check detects the failure

---

# Architecture

```text
                    Internet
                        |
                Network Load Balancer
                        |
         -------------------------------
         |                             |
    Target Group                  TCP:80
         |                             |
   ------------------           ------------------
   |                |           |                |
 EC2-Web1        EC2-Web2

```

# Task 8: Validate Using Browser

Copy the DNS name of the NLB.

Example

```
http://nlb-web-123456789.ap-south-1.elb.amazonaws.com
```

Refresh the page several times.

Expected:

* Requests are distributed to healthy targets. Because an NLB operates at Layer 4 (TCP), the backend selection depends on the TCP connection. If your browser reuses the same TCP connection (HTTP keep-alive), you may continue to see the same server.

---

# Task 9: Validate Using curl

Run:

```bash
curl http://<NLB-DNS>
```

Run multiple requests using new TCP connections:

```bash
for i in {1..10}
do
curl http://<NLB-DNS>
done
```

Or force HTTP/1.0 to reduce connection reuse:

```bash
for i in {1..10}
do
curl --http1.0 http://<NLB-DNS>
done
```

Expected: Responses may come from either Web Server 1 or Web Server 2 while both targets are healthy.

---

# Task 10: Verify Health Checks

SSH to **WebServer-1**

Stop Apache

```bash
sudo systemctl stop httpd
```

Verify

```bash
systemctl status httpd
```

Expected

```
inactive (dead)
```


# Task 12: Validate After Failure

Run

```bash
curl http://<NLB-DNS>
```

Repeat

```bash
for i in {1..10}
do
curl --http1.0 http://<NLB-DNS>
done
```

Expected

```
Welcome to Web Server 2
```

Only **Web Server 2** should respond because **Web Server 1** has failed the health checks.

---

# Task 13: Recover the Failed Server

Start Apache again

```bash
sudo systemctl start httpd
```

Check status

```bash
systemctl status httpd
```

Verify the target health after a short wait:

```
Target Groups
→ NLB-TG
→ Targets
```

Expected

```
WebServer-1    Healthy
WebServer-2    Healthy
```

---

# Task 14: Validate Again

Run

```bash
for i in {1..10}
do
curl --http1.0 http://<NLB-DNS>
done
```

Expected

```
Welcome to Web Server 1

Welcome to Web Server 2

Welcome to Web Server 1

Welcome to Web Server 2
```

Both servers should again receive traffic once the previously failed instance passes the health checks.
