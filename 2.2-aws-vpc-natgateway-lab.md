# AWS Hands-on Lab: Create a VPC with Public & Private Subnets, Internet Gateway, Regional NAT Gateway, and EC2 Instances

## Objective

In this lab, you will:

* Create a custom VPC
* Create one Public Subnet
* Create one Private Subnet
* Create an Internet Gateway
* Create Public and Private Route Tables
* Create a **Regional Public NAT Gateway**
* Launch one EC2 instance in the Public Subnet
* Launch one EC2 instance in the Private Subnet
* Connect to the Private EC2 through the Public EC2
* Verify internet connectivity from the Private EC2 using the NAT Gateway

---

# Step 1: Create a VPC

Navigate to:

```
AWS Console
→ VPC
→ Create VPC
```

Configure:

| Setting   | Value           |
| --------- | --------------- |
| Name      | StudentName-VPC |
| IPv4 CIDR | 10.0.0.0/16     |
| IPv6 CIDR | None            |
| Tenancy   | Default         |

Click **Create VPC**.

Enable:

* DNS Resolution
* DNS Hostnames

---

# Step 2: Create Public Subnet

Navigate to:

```
VPC
→ Subnets
→ Create Subnet
```

Configure:

| Setting           | Value                     |
| ----------------- | ------------------------- |
| VPC               | StudentName-VPC           |
| Name              | StudentName-Public-Subnet |
| Availability Zone | ap-south-1a               |
| IPv4 CIDR         | 10.0.1.0/24               |

After creation:

```
Actions
→ Edit subnet settings
```

Enable:

```
Auto-assign Public IPv4 Address
```

---

# Step 3: Create Private Subnet

Create another subnet.

| Setting           | Value                      |
| ----------------- | -------------------------- |

| Availability Zone | ap-south-1a                |

Configure:

| Setting | Value                 |
| ------- | --------------------- |
| Name    | StudentName-Public-RT |

| Destination | Target                             |
| ----------- | ---------------------------------- |
| 0.0.0.0/0   | Internet Gateway (StudentName-IGW) |

Associate with

```
StudentName-Public-Subnet
```

Create another route table.

| Setting | Value                  |
| ------- | ---------------------- |
| Name    | StudentName-Private-RT |
| VPC     | StudentName-VPC        |

Associate it with


---

# Step 7: Create a Regional NAT Gateway (Latest AWS Console)

Navigate to:

```
VPC
→ NAT Gateways
→ Create NAT Gateway
```

Configure:

| Setting                         | Value             |
| ------------------------------- | ----------------- |
| Name                            | StudentName-NATGW |
| Availability Zone Mode          | Regional          |
| Connectivity Type               | Public            |
| VPC                             | StudentName-VPC   |
| Method of Elastic IP Allocation | Automatic         |

Click

```
Create NAT Gateway
```

Wait until the status changes to:

```
Available
```

> **Note:** With **Regional** mode, you do not select a subnet or an Elastic IP. AWS automatically provisions and manages the Regional NAT Gateway.

# Step 14: Copy the Key to the Public EC2

From your local machine:

```bash
scp -i StudentName-Key.pem StudentName-Key.pem ec2-user@<Public-IP>:~
```

On the Public EC2:

```bash
chmod 400 StudentName-Key.pem
```

# Step 15: Connect to the Private EC2

From the Public EC2:

```bash
ssh -i StudentName-Key.pem ec2-user@<Private-IP>
```

---

# Step 16: Verify Internet Connectivity from the Private EC2

Run the following commands:

Update packages:

```bash
sudo dnf update -y
```

Install Git:

```bash
sudo dnf install git -y
```

Install Nginx:

```bash
sudo dnf install nginx -y
```

Test internet connectivity:

```bash
ping google.com
```

```bash
curl https://aws.amazon.com
```

```bash
curl ifconfig.me
```

If these commands succeed, the Private EC2 is accessing the internet through the **Regional NAT Gateway**.

# Verification Checklist

| Verification                                       | Expected Result                                |
| -------------------------------------------------- | ---------------------------------------------- |
| Public EC2 has Public IP                           | ✅ Yes                                          |
| Private EC2 has Public IP                          | ❌ No                                           |
| Internet Gateway attached to VPC                   | ✅ Yes                                          |
| Public Route Table points to IGW                   | ✅ Yes                                          |
| Private Route Table points to Regional NAT Gateway | ✅ Yes                                          |
| Public EC2 can access the Internet                 | ✅ Yes                                          |
| Private EC2 can access the Internet                | ✅ Yes                                          |
| Internet can SSH to Public EC2                     | ✅ Yes                                          |
| Internet can SSH to Private EC2                    | ❌ No                                           |
| `curl ifconfig.me` on Private EC2                  | Displays the public IP used by the NAT Gateway |
